**[ssh]**

SSH (Secure Shell) — криптографический сетевой протокол для безопасного подключения и управления.

**Типы переадресации портов SSH:**

1. **Перенаправление локального порта** (`-L`):
   ```bash
   ssh -L локальный_порт:удаленный_адрес:удаленный_порт пользователь@сервер
   ```

2. **Перенаправление удаленного порта** (`-R`):
   ```bash
   ssh -R [REMOTE:]REMOTE_PORT:DESTINATION:DESTINATION_PORT -N -f username@hostname
   ```

3. **Динамическая переадресация портов** (`-D`):
   ```bash
   ssh -D [LOCAL_IP:]LOCAL_PORT -N -f username@hostname
   ```

**[ssh-keygen]**

Генерация SSH-ключей.

`$ ssh-keygen -t rsa` — сгенерировать SSH-ключ (флаг `-t` указывает тип: RSA, dsa, ecdsa, ed25519)

*Виды SSH-ключа:*
- *Публичный* — на сервере, для шифрования
- *Приватный* — на клиенте, для расшифровки

**[ssh-copy-id]**

Утилита для копирования публичных ключей на удалённый ПК.

`$ ssh-copy-id <user@remoteserver>`

С указанием порта: `$ ssh-copy-id '-p 2202 -i ~/.ssh/id_dsa user@host'`

**Зачем использовать ключи, если можно использовать пароль?**
1. Невозможно взломать методами перебора
2. Приватный ключ недоступен из внешней сети
3. Закрытый ключ находится в каталоге без доступа для обычных пользователей
4. Для кражи нужен полный доступ к правам администратора

**Почему из Калининграда выгоднее обновлять 100-мегабайтную прошивку устройства во Владивостоке по HTTP, а не по TFTP?**
1. **Надёжность**: HTTP на TCP обеспечивает надёжную доставку, TFTP на UDP — нет
2. **Проблемы с задержками**: TCP управляет перегрузками, UDP — нет
3. **Размер пакетов**: HTTP передаёт большими блоками, TFTP — по 512 байт с подтверждением каждого
4. **Безопасность**: HTTP может работать через HTTPS (шифрование), TFTP не имеет механизмов шифрования
