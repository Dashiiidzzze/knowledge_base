### 1. Загрузка в режиме single с помощью командной строки GRUB

Для загрузки в режиме single (аварийный или однопользовательский режим) необходимо отредактировать параметры ядра в загрузчике.

**Порядок действий:**

1.  При загрузке компьютера, когда появится меню GRUB, выберите нужную запись (обычно это первая строка с актуальной версией ядра Astra Linux) и нажмите клавишу **`e`** для редактирования параметров загрузки.
2.  Найдите строку, начинающуюся с `linux`. В ней перечислены параметры, передаваемые ядру.
3.  В конце этой строки найдите параметр `quiet` и/или `splash`. После них (или вместо них) добавьте параметр **`S`** или **`single`**.
    *   *Согласно документу (стр. 5):* **`S`** – загрузить init в режиме восстановления (single).
4.  Также убедитесь, что параметр `ro` (read only) изменён на **`rw`** (read write), чтобы иметь возможность вносить изменения в файловую систему после загрузки.
5.  После внесения изменений нажмите **`Ctrl+X`** или **`F10`** для загрузки с этими параметрами.

**Пример строки ДО изменений:**
`linux /boot/vmlinuz-... root=UUID=... ro quiet splash`

**Пример строки ПОСЛЕ изменений для загрузки в single:**
`linux /boot/vmlinuz-... root=UUID=... rw single`

Система загрузится в однопользовательском режиме, где вы окажетесь с правами root без необходимости ввода пароля.

### 2. Смена пароля GRUB, установка таймаута 3с без показа меню

Эти настройки изменяются в конфигурационном файле `/etc/default/grub`. **Нельзя редактировать `/boot/grub/grub.cfg` напрямую**, так как он генерируется автоматически.

**Порядок действий:**

1.  Откройте файл конфигурации в текстовом редакторе с правами root:
    ```bash
    sudo nano /etc/default/grub
    ```

2.  **Установите таймаут и скройте меню:**
    Найдите и измените/добавьте следующие строки:
    ```bash
    GRUB_TIMEOUT=3           # Таймаут показа меню в секундах
    GRUB_TIMEOUT_STYLE=countdown # Стиль - обратный отсчет
    GRUB_HIDDEN_TIMEOUT=3    # Скрыть меню на время обратного отсчета
    GRUB_HIDDEN_TIMEOUT_QUIET=true # Не показывать обратный отсчет (опционально, для полной тишины)
    ```

3.  **Установите пароль для GRUB:**
    *   Сгенерируйте хэш пароля. В терминале выполните команду:
        ```bash
        grub-mkpasswd-pbkdf2
        ```
        Введите желаемый пароль. Команда выдаст хэш (начинается с `grub.pbkdf2...`). Скопируйте его.
    *   Добавьте в файл `/etc/default/grub` строки для пользователя `root` (или другого):
        ```bash
        GRUB_PASSWORD=grub.pbkdf2.sha512.10000.[Ваш_Длинный_Хэш]
        ```

4.  **Примените изменения,** сгенерировав новый `grub.cfg`:
    ```bash
    sudo update-grub
    ```
    *Команда `update-grub` является скриптом-обёрткой для `grub-mkconfig -o /boot/grub/grub.cfg` (как указано на стр. 6 документа).*

После перезагрузки меню GRUB будет скрыто, в течение 3 секунд будет идти обратный отсчет, а для его отображения и редактирования параметров загрузки потребуется нажать `Esc` и ввести логин (`root`) и установленный пароль.

### 3. Создание unit-файла (service) для включения маршрутизации в ядре

Включение маршрутизации (`net.ipv4.ip_forward=1`) — это изменение параметра ядра. Проще всего сделать это с помощью sysctl, но для работы через systemd создадим службу, которая выполнит эту команду при запуске системы.

**Порядок действий:**

1.  Создайте unit-файл с именем, например, `ip-forwarding.service`. По правилам systemd его нужно разместить в `/etc/systemd/system/`.
```bash
    sudo nano /etc/systemd/system/ip-forwarding.service
```

2.  Наполните файл следующим содержимым. Это стандартный шаблон юнита типа service (описан на стр. 13-14 документа):
```ini
    [Unit]
    Description=Enable IP Forwarding in kernel
    # Запускаться после того, как сеть будет поднята
    After=network.target
    # Указываем, что это однократная задача, а не постоянно работающая служба
    DefaultDependencies=no

    [Service]
    Type=oneshot
    # Сама команда, которая выполняется при старте службы
    ExecStart=/sbin/sysctl -w net.ipv4.ip_forward=1
    # Гарантируем, что параметр будет установлен в 1
    RemainAfterExit=yes

    [Install]
    # Указываем, что служба должна быть запущена при переходе в multi-user target
    WantedBy=multi-user.target
```

3.  Сохраните файл и закройте редактор.

4.  Разрешите systemd загружать новый юнит и добавьте его в автозагрузку:
```bash
    sudo systemctl daemon-reload        # Перечитать конфигурацию юнитов
    sudo systemctl enable ip-forwarding.service # Включить автозапуск
    sudo systemctl start ip-forwarding.service  # Запустить службу сейчас
```

5.  **Проверьте результат:**
    *   Проверьте статус службы:
        ```bash
        systemctl status ip-forwarding.service
        ```
    *   Убедитесь, что параметр ядра изменился:
        ```bash
        cat /proc/sys/net/ipv4/ip_forward
        ```
        В выводе должна быть цифра `1`.

Теперь при каждой загрузке системы ваш unit-файл будет активировать функцию маршрутизации на уровне ядра.




# Управление программным обеспечением

#### 1. Установка программного обеспечения FTP сервера: vsftpd.
Для установки пакета `vsftpd` используется менеджер пакетов `apt`.
```bash
sudo apt update
sudo apt install vsftpd
```

#### 2. Проверка статуса FTP сервера.
Статус службы проверяется с помощью утилиты `systemctl`.
```bash
sudo systemctl status vsftpd
```
В выводе команды проверяется, что служба активна (active) и работает (running).

#### 3. Разрешение анонимной аутентификации в /etc/vsftpd.conf.
Конфигурационный файл редактируется в текстовом редакторе. В файле находится строка `anonymous_enable=NO` и меняется на `YES`.
```bash
sudo nano /etc/vsftpd.conf
```
После внесения изменения файл сохраняется.

#### 4. Перечитывание конфигурационного файла FTP сервером.
Для применения новых настроек служба не перезапускается полностью, а лишь перечитывает конфигурационный файл. Это делается с помощью команды `systemctl reload`.
```bash
sudo systemctl reload vsftpd
```

#### 5. Установка утилиты reprepro.
Утилита `reprepro` используется для создания и управления локальными репозиториями Debian.
```bash
sudo apt install reprepro
```

#### 6. Создание каталога для репозитория в /srv/ftp.
Каталог создается с помощью команды `mkdir`. Имя каталога может быть любым, например, `myrepo`.
```bash
sudo mkdir -p /srv/ftp/myrepo
```

#### 7. Создание конфигурационного файла distributions.
В каталоге репозитория создается подкаталог `conf`, а в нем — файл `distributions`.
```bash
sudo nano /srv/ftp/myrepo/conf/distributions
```
В файл вносится следующая конфигурация (параметры заполняются в соответствии с нуждами):
```ini
Origin: My Organization
Label: MyRepo
Codename: myrepo
Suite: stable
Version: 1.0
Architectures: amd64
Components: main
Description: My local repository
SignWith: yes
```

#### 8. Создание ключей для репозитория.
Для подписи репозитория требуется ключ GPG. Создается он командой:
```bash
sudo gpg --gen-key
```
В процессе указывается имя (например, "MyRepo"), email и парольная фраза. Для ускорения генерации энтропии можно на другом терминале выполнить команду, создающую нагрузку (например, `sudo dd if=/dev/sda of=/dev/null`).

#### 9. Создание структуры репозитория с помощью reprepro.
Команда `reprepro` инициализирует структуру каталогов репозитория в указанной папке.
```bash
cd /srv/ftp/myrepo
sudo reprepro --ask-passphrase -b . export
```
Вводится парольная фраза от GPG-ключа.

#### 10. Скачивание deb-пакета Zoom.
Пакет скачивается с официального сайта с помощью утилиты `wget`.
```bash
wget https://zoom.us/client/latest/zoom_amd64.deb -O /tmp/zoom_amd64.deb
```

#### 11. Добавление пакета Zoom в репозиторий.
Пакет добавляется в репозиторий с указанием кодового имени и компонента.
```bash
sudo reprepro --ask-passphrase -b /srv/ftp/myrepo includedeb myrepo /tmp/zoom_amd64.deb
```
Снова вводится парольная фраза.

#### 12. Экспорт публичного ключа репозитория.
Публичный ключ экспортируется в файл для последующего распространения.
```bash
sudo gpg --armor --output /tmp/myrepo.gpg.key --export "MyRepo"
```

#### 13. Добавление ключа в хранилище truststore apt.
Ключ добавляется в систему, чтобы `apt` доверял пакетам из репозитория, подписанным этим ключом.
```bash
sudo apt-key add /tmp/myrepo.gpg.key
```

#### 14. Подключение репозитория с помощью apt edit-sources.
Команда `apt edit-sources` открывает для редактирования файл со списком репозиториев.
```bash
sudo apt edit-sources
```
В открывшийся редактор добавляется строка:
```
deb [arch=amd64] ftp://localhost/myrepo myrepo main
```
Файл сохраняется.

#### 15. Обновление кэша и установка zoom.
Перед установкой пакета необходимо обновить локальную информацию о доступных пакетах.
```bash
sudo apt update
sudo apt install zoom
```



# **Управление файловыми системами**

### Задание 1. Добавление двух дисков в виртуальной машине.

**Выполняется в интерфейсе гипервизора (VirtualBox, VMware и т.д.).**
1.  Выключается виртуальная машина.
2.  В настройках ВМ переходят в раздел "Носители" или "Диски".
3.  Добавляется два новых виртуальных жестких диска (например, по 10-20 Гб каждый).
4.  Виртуальная машина запускается.

### Задание 2. Разметка дисков.

После загрузки системы необходимо определить имена добавленных дисков. Это можно сделать командой:
```bash
lsblk
```
В выводе команды, помимо основного диска (например, `sda` или `vda`), можно увидеть два новых диска без разделов (например, `sdb` и `sdc`).

**Разметка первого диска (например, `/dev/sdb`) с помощью `fdisk`:**
```bash
sudo fdisk /dev/sdb
```
*В интерактивном режиме `fdisk` выполняются следующие команды (см. стр. 39-40):*
1.  `g` — создается новая пустая таблица разделов GPT.
2.  `n` — создается новый раздел. Принимаются значения по умолчанию для первого раздела (номер 1, первый сектор). Для размера указывается `+XG` (например, `+10G` для половины диска 20Гб).
3.  `n` — создается второй раздел. Снова принимаются значения по умолчанию (номер 2, оставшееся пространство).
4.  `w` — таблица разделов записывается на диск, и `fdisk` завершает работу.

**Разметка второго диска (например, `/dev/sdc`) с помощью `parted`:**
```bash
sudo parted /dev/sdc
```
*В интерактивном режиме `parted` выполняются следующие команды (см. стр. 41):*
1.  `mktable gpt` — создается таблица разделов GPT.
2.  `unit MiB` — устанавливаются единицы измерения — МиБ.
3.  `mkpart primary 1MiB 10241MiB` — создается первый раздел размером ~10 GiB (10240 MiB + 1 MiB для выравнивания).
4.  `mkpart primary 10241MiB 100%` — создается второй раздел на оставшемся пространстве.
5.  `print` — проверяется правильность создания разделов.
6.  `quit` — выход из `parted`.

Для применения изменений ядром после работы с `parted` может потребоваться выполнить команду:
```bash
sudo partprobe
```

### Задание 3. Создание файловых систем.

Предполагается, что после разметки на каждом диске есть по два раздела: `sdb1`, `sdb2`, `sdc1`, `sdc2`.

**На первых разделах (`sdb1`, `sdc1`) создается файловая система ext4:**
```bash
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.ext4 /dev/sdc1
```

**На вторых разделах (`sdb2`, `sdc2`) создается файловая система ext2:**
```bash
sudo mkfs.ext2 /dev/sdb2
sudo mkfs.ext2 /dev/sdc2
```

### Задание 4. Создание точек монтирования.

Создается необходимое дерево каталогов:
```bash
sudo mkdir -p /opt/data/{storage,cache,export,log}
```

### Задание 5. Настройка автоматического монтирования.

**Для первого диска (например, `/dev/sdb1` и `/dev/sdb2`) используется `/etc/fstab`.**

1.  Определяется UUID разделов (предпочтительный метод):
    ```bash
    sudo blkid
    ```
2.  В файл `/etc/fstab` добавляются строки. Например, для разделов `sdb1` (ext4) и `sdb2` (ext2):
    ```
    UUID=<UUID_sdb1> /opt/data/storage ext4 defaults 0 2
    UUID=<UUID_sdb2> /opt/data/cache    ext2 defaults 0 2
    ```
    *Где `<UUID_sdb1>` и `<UUID_sdb2>` заменяются на реальные значения из вывода `blkid`.*

**Для второго диска (например, `/dev/sdc1` и `/dev/sdc2`) создаются юниты systemd типа mount.**

1.  Создается юнит для первого раздела (`sdc1`), который будет монтироваться в `/opt/data/export`:
```bash
    sudo systemctl --force edit opt-data-export.mount
```

В редактор вводится следующее содержимое (UUID заменяется на реальное значение):
```ini
    [Unit]
    Description=Mount /dev/sdc1 to /opt/data/export

    [Mount]
    What=UUID=<UUID_sdc1>
    Where=/opt/data/export
    Type=ext4
    Options=defaults

    [Install]
    WantedBy=multi-user.target
```
Файл сохраняется. Аналогично создается юнит для второго раздела (`sdc2`), монтируемого в `/opt/data/log`:
```bash
    sudo systemctl --force edit opt-data-log.mount
```
*Содержимое юнита:*
```ini
    [Unit]
    Description=Mount /dev/sdc2 to /opt/data/log

    [Mount]
    What=UUID=<UUID_sdc2>
    Where=/opt/data/log
    Type=ext2
    Options=defaults

    [Install]
    WantedBy=multi-user.target
```
2.  Активируется автозагрузка созданных юнитов:
    ```bash
    sudo systemctl enable opt-data-export.mount
    sudo systemctl enable opt-data-log.mount
    ```
3.  Для применения изменений без перезагрузки можно выполнить:
    ```bash
    sudo systemctl start opt-data-export.mount
    sudo systemctl start opt-data-log.mount
    ```

### Задание 6. Проверка работы.

Выполняется перезагрузка системы:
```bash
sudo reboot
```
После загрузки проверяется, что все файловые системы смонтированы в целевые каталоги:
```bash
df -h /opt/data/storage /opt/data/cache /opt/data/export /opt/data/log
```
Также проверяется статус юнитов mount:
```bash
systemctl status opt-data-export.mount opt-data-log.mount
```
В выводе команд должно быть видно, что файловые системы присутствуют и смонтированы, а службы находятся в активном (active) состоянии.
