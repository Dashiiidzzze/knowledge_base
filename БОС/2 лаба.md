# 1 задание
Сообщение **`GNU GRUB version 2.02 Minimal BASH-like line editing is supported...`** с последующим приглашением **`grub >`** или **`grub rescue >`** означает, что первая стадия загрузчика GRUB загрузилась, но он не может найти свой конфигурационный файл (`grub.cfg`) или файлы ядра в разделе `/boot`.

Это **классический случай повреждения загрузчика**, который идеально соответствует заданию.

# 2 задание
Поскольку мы видим приглашение `grub>`, это значит, что мы можем попытаться восстановить загрузку вручную, чтобы потом окончательно всё починить. Это быстрее, чем загружаться с установочного диска.

**Попробуй этот способ сначала (через встроенные команды GRUB):**

1. **Находясь в командной строке `grub>`, нам нужно найти корневой раздел, где лежат файлы GRUB и ядро.**
    
    - Введи команду, чтобы посмотреть все диски и разделы, которые видит GRUB:
```bash
        ls
```
 Вывод будет примерно таким: `(hd0) (hd0,msdos1) (hd0,msdos2)` или `(hd0) (hd0,gpt1) (hd0,gpt2)`. Это список дисков и разделов.

2.  **Просканируем каждый раздел, чтобы найти наш корневой раздел:**
    Ты уже проверил `(hd0,msdos1)`. Проверь следующий:
    ```bash
    ls (hd0,msdos2)/
    ```
    *   **Если снова ошибка `unknown filesystem`** — переходи к следующему разделу: `ls (hd0,msdos3)/` и так далее.
    *   **Если команда выполнится успешно**, ты увидишь список файлов и папок на этом разделе. Это то, что нам нужно!

3.  **Что мы ищем:**
    Нам нужно найти раздел, в котором есть папка `boot` с содержимым примерно таким:
    ```
    grub/ grub2/ initrd.img-4.15.3-1-generic vmlinuz-4.15.3-1-generic ...
    ```
    **ИЛИ** (если у тебя нет отдельного раздела `/boot`) раздел, в котором сразу есть папки:
    ```
    bin/ boot/ dev/ etc/ home/ ...
    ```

4.  **Допустим, нам повезло, и мы нашли нужный раздел. Пусть это будет `(hd0,msdos2)`.** Тогда загружаем систему вручную:

    a) **Скажи GRUB, что этот раздел — наш корень:**
    ```bash
    set root=(hd0,msdos2)
    ```

    b) **Загрузи ядро Linux.** Используй табуляцию (`Tab`) после `vmlinuz-` и `initrd.img-`, чтобы автоматически подставить версию ядра.
    ```bash
    linux /boot/vmlinuz-<нажми Tab> root=/dev/sda2 ro
    ```
    **Важно:** Замени `sda2` на устройство, соответствующее твоему разделу. `(hd0,msdos2)` обычно это `/dev/sda2`. Параметр `ro` означает read-only (только для чтения) при старте.
    **Выбирай вариант `generic`.**

**Выбирай вариант `generic`** Вот почему:
1. **`generic`** — это стандартное, универсальное ядро, предназначенное для большинства систем. Оно используется по умолчанию.
2. **`hardened`** — это специальная, усиленная с точки зрения безопасности версия ядра. Оно используется в особых режимах работы Astra Linux (например, в "режиме безопасности") и может иметь особенности работы с оборудованием или драйверами. Если выбрать `hardened` и система на него не настроена, есть риск, что она не загрузится корректно.

    c) **Загрузи образ initrd:**
    ```bash
    initrd /boot/initrd.img-<нажми Tab>
    ```
	тоже generic
	
    d) **Запусти загрузку:**
    ```bash
    boot
    ```

### Если ни на одном разделе не находится файловая система (все команды `ls` возвращают ошибку)

Это серьезный признак того, что:
*   **Либо файловая система сильно повреждена.**
*   **Либо диск зашифрован (например, через LUKS), и GRUB не может его прочитать без ключа.**

**В этом случае единственный надежный вариант — действовать по первоначальному плану с установочным диском (стр. 6-14 пособия).**

1.  **Загрузись с установочного диска Astra Linux.**
2.  **Выбери «Режим восстановления».**
3.  **На шаге «Выбор корневого раздела» (стр. 9-10) выбери вариант:**
    **`Не использовать корневую файловую систему`**.
4.  Это позволит запустить оболочку установщика. Оттуда можно попробовать проанализировать состояние дисков утилитами (`fdisk -l`, `fsck`). Но наша главная цель — **восстановить загрузчик**.
5.  Из этой оболочки можно попробовать вручную смонтировать корневой раздел и переустановить GRUB, если ты сможешь его найти.
