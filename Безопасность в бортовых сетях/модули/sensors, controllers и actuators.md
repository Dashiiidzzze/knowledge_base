### Описание текущего взаимодействия:

1. **Сенсоры (sensors)** генерируют случайные данные телеметрии каждую секунду:
    - Температура, давление, вибрация
    - Отправляют данные на UDP-порт 9000 модуля controllers
2. **Контроллеры (controllers)** получают телеметрию от сенсоров:
    - Анализируют значения телеметрии
    - При превышении пороговых значений (температура > 80°C или вибрация > 4.0 m/s²) генерируют команду SHUTDOWN_ENGINE
    - Отправляют команду на UDP-порт 9100 модуля actuators
3. **Актуаторы (actuators)** обрабатывают команды от контроллеров:
    - Получают команды по UDP
    - Имитируют выполнение действий (логирование)

### Уязвимости и проблемы архитектуры:

1. **Отсутствие аутентификации и шифрования:**
    - Весь обмен данными происходит по UDP без шифрования
    - Нет механизма проверки подлинности сообщений
    - **Уязвимые порты:** UDP 9000 и 9100
    - **Уязвимая конфигурация:** Отсутствие аутентификации отправителя
2. **Недостаточная валидация данных:**
    - Контроллер не проверяет источник сообщений
    - Актуаторы принимают и выполняют команды без проверки авторизации
    - **Уязвимость:** Возможность отправки ложных команд актуаторам
3. **Отсутствие резервирования:**
    - Единственный канал связи между модулями
    - Нет механизма подтверждения доставки сообщений
    - **Архитектурная проблема:** Потеря сообщений не отслеживается
4. **Изолированный поток данных:**
    - Данные от сенсоров не публикуются в центральной шине для других компонентов
    - Модуль `avionics` не интегрирован в этот поток данных
    - **Архитектурная проблема:** Отсутствие централизованного мониторинга


### Сравнение с реальными бортовыми сетями:

В реальных бортовых сетях взаимодействие между сенсорами, контроллерами и актуаторами имеет следующие отличия от вашей модели:

1. **Протоколы передачи данных:**
    - **Реальные сети:** Используются специализированные протоколы ARINC 429, 664 (AFDX), или ARINC 825 (CAN)
    - **Ваша модель:** Простой UDP без детерминированных гарантий передачи
2. **Безопасность и надежность:**
    - **Реальные сети:** Множественное резервирование, проверка целостности данных, защита от ошибок
    - **Ваша модель:** Отсутствие механизмов проверки доставки и резервирования
3. **Централизованное управление:**
    - **Реальные сети:** Интеграция с центральными системами обработки данных
    - **Ваша модель:** Изолированный поток данных, не связанный с центральной системой avionics


## Рекомендации по улучшению:

### Для цепочки sensors → controllers → actuators:

1. **Усиление безопасности:**
    - Добавить механизм аутентификации сообщений (например, HMAC)
    - Реализовать шифрование данных для защиты от перехвата
    - Добавить фильтрацию по IP-адресам для проверки источника
2. **Повышение надежности:**
    - Реализовать подтверждение доставки критичных сообщений
    - Добавить резервные каналы связи
    - Реализовать механизм выявления и обработки дублированных сообщений
3. **Интеграция с центральной системой:**
    - Добавить публикацию данных телеметрии в MQTT для центрального модуля `avionics`
    - Реализовать дублирование критичных команд через `avionics`
    - Создать централизованный журнал событий через `avionics`
