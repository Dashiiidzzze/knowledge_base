**Hot** **Standby** **Router** **Protocol** - протокол горячего резервирования маршрутизаторов - это запатентованный Cisco протокол FHRP, который позволяет двум или более маршрутизаторам работать вместе, выступая в качестве высокодоступного шлюза по умолчанию для локальных хостов. HSRP работает по модели «активный/резервный» и реализует концепцию виртуального IP-адреса (VIP), как показано на схеме ниже.

VRRP — его аналог, который, в свою очередь, является открытым протоколом, выполняет ту же роль.

Обратите внимание, что физический интерфейс R1 имеет IP-адрес 10.1.1.2, а физический интерфейс R2 — 10.1.1.3. Однако оба маршрутизатора поддерживают протокол HSRP и используют общий виртуальный IP-адрес 10.1.1.1. Виртуальный IP-адрес — это обычный IP-адрес в той же локальной подсети, но он не настроен ни на одном физическом интерфейсе маршрутизатора (отсюда и название «виртуальный»).

Обработка пакетов происходит не параллельно, а по принципу «работает сильнейший». В случае выхода из строя активного маршрутизатора, вместо него автоматически начинает работать второй и дальше по списку, в зависимости от количества маршрутизаторов в HSRP-групп

Отличный вопрос! Давайте разберёмся, зачем **активный (Active) маршрутизатор** в **HSRP** постоянно отправляет **Hello-пакеты**, даже если его статус уже известен другим устройствам.

## 1. Для чего нужны Hello-пакеты в HSRP?
HSRP (Hot Standby Router Protocol) — это протокол резервирования шлюзов, и его работа основана на **обмене мультикаст-сообщениями** (`224.0.0.2`, UDP порт 1985). Hello-пакеты выполняют **три ключевые функции**:
### 1. Поддержание "живучести" (Liveness Detection)
- **Активный роутер (Active)** отправляет Hello-пакеты **каждые 3 секунды** (по умолчанию), чтобы сообщить резервному (Standby), что он ещё "жив".
- **Резервный роутер (Standby)** ждёт эти сообщения. Если **Hello не приходят в течение 10 секунд** (Hold Timer), он считает Active "мёртвым" и берёт на себя его роль.

### 2. Выбор Active и Standby
- Hello-пакеты содержат:
  - **Приоритет (Priority)** — кто станет Active (чем выше, тем приоритетнее).
  - **Состояние (State)** — Active, Standby, Listening и др.
- Если два роутера запускают HSRP одновременно, они **сравнивают приоритеты** через Hello и выбирают роли.

### 3. Поддержка Preempt (перехват роли)
- Если **Standby роутер** имеет **более высокий приоритет**, чем текущий Active, он может **перехватить** роль, отправив Hello с флагом **Preempt**.
- Без Hello механизм Preempt не сработает.




# **Настройка HSRP на роутерах**
### **2. Настройка IP-адресов**
**R1:**
```bash
enable
configure terminal
hostname R1
!
interface GigabitEthernet0/0
 ip address 10.10.10.1 255.255.255.0  # R1 получает реальный IP
 no shutdown
!
standby 1 ip 10.10.10.52  # Виртуальный IP для HSRP
standby 1 priority 110    # R1 — активный (приоритет выше)
standby 1 preempt         # Возвращает роль активного после перезагрузки
!
end
write
```

 **R2:**
```bash
enable
configure terminal
hostname R2
!
interface GigabitEthernet0/0
 ip address 10.10.10.2 255.255.255.0  # R2 получает реальный IP
 no shutdown
!
standby 1 ip 10.10.10.52  # Тот же виртуальный IP, что и на R1
standby 1 priority 100    # R2 — резервный (приоритет ниже)
standby 1 preempt         # Может стать активным, если R1 отключится
!
end
write
```

#### **Виртуальный компьютер (VPCS):**
```bash
ip 10.10.10.3 10.10.10.52  # IP компьютера и шлюз (виртуальный IP HSRP)
save
```

---
### **3. Проверка работы HSRP**
#### **На R1 и R2 выполните:**
```bash
show standby brief
```
Вывод должен показать:
- **R1** — `Active` (приоритет 110)
- **R2** — `Standby` (приоритет 100)
- Виртуальный IP: `192.168.1.1`

#### **Проверка связности с компьютера:**
```bash
ping 192.168.1.1  # Проверка виртуального шлюза
ping 192.168.1.2  # Проверка R1
ping 192.168.1.3  # Проверка R2
```

---

1. **Отключите R1** (например, выключите интерфейс `Gi0/0`):
   ```bash
   interface Gi0/0
    shutdown
   ```
2. **Проверьте на R2:**
   ```bash
   show standby brief
   ```
   Теперь R2 должен стать `Active`.
3. **Проверьте с компьютера:**
   ```bash
   ping 192.168.1.1  # Пинг должен проходить через R2
   ```
